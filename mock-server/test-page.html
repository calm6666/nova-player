hilihili 播放器 mock-server 自测页

本页只做「接口体检」：显示各接口的原始返回，方便把「数据不对」和「播放器画得不对」分开排查。 服务根地址

怎么用（照着做就行）

  1. 起服务（在 front/player/mock-server 目录下）： 
    node server.js --port 9101 --video "D:\你的片子.mp4"
    不带 --video 也能起，只是雪碧图/bin 时间表不可用（接口 404）、片长按 600 秒算（其余接口全部正常）。
  2. 浏览器打开 http://127.0.0.1:9101/ ——必须通过服务访问这个地址，不要双击用 file:// 打开本文件， 否则页面里的请求会指向 file:///x/player/v2 这种不存在的磁盘路径（EventSource 在 file:// 下也不可用）。
  3. 页面上往下依次是：运行环境（片长来源、弹幕条数、ffmpeg 是否可用、预览图状态）→ 接口一览（点「请求」看每项的 URL 与返回前 200 字符） → 发弹幕（POST /danmaku/send）→ SSE 实时弹幕（/danmaku/stream，发完立刻能看到） → WebSocket 实时弹幕（ws://…/danmaku/ws，双向：既能实时收，也能直接发） → 分段 + 高能曲线 → 进度条预览（B 站 videoshot：雪碧图裁切 + bin 时间表）。
  4. 每一块的输出里都带了请求 URL和返回片段，直接复制就能贴进联调记录； 想手测某个接口也可以直接用 curl http://127.0.0.1:9101/x/player/v2?aid=123&cid=456。
  5. WebSocket 面板优先走 WS 发送（验证双向链路）：连接正常时点「通过 WS 发送」，消息会走 {"type":"send",…} 上行、再以 {"type":"danmaku",…} 广播回来，自己和别的标签页都能看到； WS 断开时同一个按钮会自动降级成 POST（面板上会写明用的是哪条路）。区块里的「发送 ping」用来量 WS 往返延迟。 心跳是协议层 ping 帧（浏览器在底层自动回 pong，JS 看不到），页面只能显示服务端在 hello 里报的心跳间隔。
页面里所有请求都是相对路径（同源），所以换端口、换 --host、从别的机器访问都不用改代码。

进度条预览（GET /x/player/videoshot，B 站形状）

接口返回 data.{pvdata, img_x_len, img_y_len, img_x_size, img_y_size, image[], index[]}： image 是雪碧图拼版数组（每张 img_x_len × img_y_len = 100 格，帧多时多张拼版）； pvdata 指向 bin 截取时间表——uint16 小端数组，第 0 项恒为 0（占位）， 第 k 项是第 k 张截图的秒数（B 站按画面变化程度不均匀截图，所以需要这份「帧 ↔ 时间」映射； 本 mock 等间隔 5 秒抽帧，时间表是等差数列，格式与 B 站一致）。 取第 t 秒的帧 = 时间表里找「最后一个 ≤ t」的项 i → 帧 k = i−1 → 拼版 floor(k / 100)、列 k % img_x_len、行 floor((k%100) / img_x_len)。 请求带 index=1 时 data.index 直接给同一份时间表的 JSON 数组（免解析 bin）。
