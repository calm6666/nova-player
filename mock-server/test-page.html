hilihili 播放器 mock-server 自测页

本页只做「接口体检」：显示各接口的原始返回，方便把「数据不对」和「播放器画得不对」分开排查。 服务根地址

怎么用（照着做就行）

  1. 起服务（在 front/player/mock-server 目录下）： 
    node server.js --port 9101 --video "D:\你的片子.mp4"
    不带 --video 也能起，只是 preview.bin 是空文件、片长按 600 秒算（其余接口全部正常）。
  2. 浏览器打开 http://127.0.0.1:9101/ ——必须通过服务访问这个地址，不要双击用 file:// 打开本文件， 否则页面里的请求会指向 file:///x/player/v2 这种不存在的磁盘路径（EventSource 在 file:// 下也不可用）。
  3. 页面上往下依次是：运行环境（片长来源、弹幕条数、ffmpeg 是否可用、预览图状态）→ 接口一览（点「请求」看每项的 URL 与返回前 200 字符） → 发弹幕（POST /danmaku/send）→ SSE 实时弹幕（/danmaku/stream，发完立刻能看到） → WebSocket 实时弹幕（ws://…/danmaku/ws，双向：既能实时收，也能直接发） → 分段 + 高能曲线 → 缩略图网格（/videoshot/preview.bin 的前 20 帧）。
  4. 每一块的输出里都带了请求 URL和返回片段，直接复制就能贴进联调记录； 想手测某个接口也可以直接用 curl http://127.0.0.1:9101/x/player/v2?aid=123&cid=456。
  5. WebSocket 面板优先走 WS 发送（验证双向链路）：连接正常时点「通过 WS 发送」，消息会走 {"type":"send",…} 上行、再以 {"type":"danmaku",…} 广播回来，自己和别的标签页都能看到； WS 断开时同一个按钮会自动降级成 POST（面板上会写明用的是哪条路）。区块里的「发送 ping」用来量 WS 往返延迟。 心跳是协议层 ping 帧（浏览器在底层自动回 pong，JS 看不到），页面只能显示服务端在 hello 里报的心跳间隔。
页面里所有请求都是相对路径（同源），所以换端口、换 --host、从别的机器访问都不用改代码。

预览缩略图（GET /videoshot/preview.bin，前 20 张）

每 5 秒 1 帧：整个文件按 \u001F 切分后，arr[0] 是空占位（永远不用）， arr[k] 是第 5*(k-1) 秒的帧。 播放器就是这么取的（controls/index.ts:1410-1417）： videoshot[Math.floor(当前秒 / 5) + 1]； 反查：t=0/4→下标 1，t=5→下标 2，t=12→下标 3。

雪碧图预览模式（GET /videoshot/sprite.jpg）

和上面的 preview.bin（逐帧 data URL 列表）并列的第二种预览数据源：一张真实图片。 参数从 /videoshot/index.json 的 pvdata 拿（B 站形状）： img_x_len × img_y_len 网格、每格 img_x_size × img_y_size； 取第 t 秒的帧 = 切片下标 Math.floor(t / 5) → 列 下标 % img_x_len、行 Math.floor(下标 / img_x_len)。 两种模式按需取用（雪碧图 = 一次 HTTP 拿全部帧；bin = 无需知道尺寸直接当 img src）。
